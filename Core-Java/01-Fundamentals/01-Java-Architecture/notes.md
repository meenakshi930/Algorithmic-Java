1. Java Architecture: JDK, JRE, JVM
1.1 What is Java?
Java is a high-level, class-based, object-oriented programming language. Java source code is compiled into bytecode, which can be executed by a compatible Java Virtual Machine (JVM).

Important characteristics:
- Platform independent bytecode: The same bytecode can run on different operating systems when a compatible JVM is available.
- Object-oriented: Programs can be organized using classes and objects.
- Robust: Provides type checking, exception handling, and automatic memory management.
- Multithreaded: Supports concurrent execution.
- Portable: Java defines consistent language and runtime behavior across platforms.
The phrase Write Once, Run Anywhere (WORA) describes Java's bytecode portability. It does not mean every Java program is automatically independent of operating-system-specific libraries or native code.

1.2 How a Java program executes
Example source file: Hello.java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
Execution steps:
1. Write source code in a .java file.
2. Compile it using the Java compiler (javac).
3. The compiler generates bytecode in a .class file.
4. The JVM loads, verifies, and executes the bytecode.
5. The program produces output.
Commands:
javac Hello.java
java Hello
Expected output:
Hello, Java!
Remember:
Term	Meaning
.java	Java source-code file
.class	Compiled bytecode file
javac	Java compiler
java	Java application launcher

1.3 JVM — Java Virtual Machine
The JVM is an abstract computing machine that executes Java bytecode. JVM implementations are specific to operating systems and hardware platforms.

Main responsibilities:
- Loads classes.
- Verifies bytecode.
- Creates and manages runtime memory areas.
- Executes bytecode.
- Uses Just-In-Time (JIT) compilation to optimize frequently executed code.
- Reclaims eligible memory through garbage collection.
- Supports threads and synchronization.
Important JVM runtime areas
Area	Purpose
Heap	Stores objects and arrays; shared among application threads
Java stack	Stores per-thread stack frames for method calls, local variables, and intermediate results
PC register	Tracks the current bytecode instruction for each thread
Method area	Stores class-level structures and runtime metadata
Native method stack	Supports execution of native methods


The JVM also has a class-loading subsystem and an execution engine. The execution engine uses an interpreter and may use a JIT compiler.

Garbage collection: The JVM can reclaim heap memory occupied by objects that are no longer reachable. Developers do not normally free objects manually.
1.4 JRE — Java Runtime Environment
The JRE is the conceptual runtime environment required to run Java applications. It includes the JVM and runtime libraries/supporting components.

A runtime installation does not need development tools such as the Java compiler.
1.5 JDK — Java Development Kit
The JDK is the development kit used to build Java applications. It provides the runtime components plus development tools.

Common tools include:
- javac — compiler
- java — application launcher
- javadoc — documentation generator
- jar — archive tool
- jshell — interactive Java shell
Modern JDK distributions may package runtime components differently. The JDK/JRE/JVM distinction remains useful as a conceptual model.
1.6 JDK vs JRE vs JVM
Component	Main purpose	Key point
JDK	Develop and run Java applications	Includes development tools
JRE	Provide the runtime environment	Includes JVM and runtime libraries conceptually
JVM	Execute Java bytecode	Platform-specific implementation


Memory aid:
- JDK: Develop.
- JRE: Run.
- JVM: Execute bytecode.

1.7 Bytecode, interpreter, and JIT
- Bytecode: Intermediate instructions generated by the Java compiler and stored in .class files.
- Interpreter: Executes bytecode instructions.
- JIT compiler: Compiles frequently executed code into native machine code at runtime to improve performance.
Java is not simply interpreted or simply compiled: source code is compiled to bytecode, and the JVM uses runtime execution and optimization techniques.

2. Data Types and Variables
2.1 What is a variable?
A variable is a named storage location that holds a value during program execution.
int age = 20;
- int — data type
- age — variable name
- 20 — value
- = — assignment operator
General syntax:
dataType variableName = value;
Declaration and initialization can also be separate:
int marks;   // declaration
marks = 90;  // initialization
2.2 Java data-type categories
Java data types are commonly divided into:
1. Primitive types
2. Reference types (often called non-primitive types in introductory material)
A. Eight primitive data types
Type	Width	General use	Example
byte	8 bits	Small integers	byte x = 10;
short	16 bits	Small-range integers	short x = 1000;
int	32 bits	General integer values	int x = 50000;
long	64 bits	Large integer values	long x = 9000000000L;
float	32 bits	Single-precision decimal	float x = 2.5f;
double	64 bits	Double-precision decimal	double x = 2.5;
char	16 bits	One UTF-16 code unit	char grade = 'A';
boolean	Not specified as a fixed storage width by Java	Logical true/false	boolean passed = true;


Important details:
- byte range: -128 to 127.
- short range: -32,768 to 32,767.
- int range: -2³¹ to 2³¹ - 1.
- long range: -2⁶³ to 2⁶³ - 1.
- float and double use binary floating-point representations; many decimal fractions cannot be represented exactly.
- A long literal commonly uses the L suffix.
- A float literal requires the f or F suffix.
- Decimal literals are double by default.
- A char uses single quotes and represents one UTF-16 code unit. A Unicode supplementary character may require two char values.
Examples:
byte smallNumber = 100;
short marks = 30000;
int population = 1000000;
long distance = 9000000000L;

float price = 99.5f;
double percentage = 87.456;

char grade = 'A';
boolean isPassed = true;
B. Reference types
Reference types include:
- Classes, such as String and user-defined classes
- Arrays
- Interfaces
- Enums
- Records and other class-like types
Examples:
String name = "Java";
int[] numbers = {10, 20, 30};
A reference variable holds a reference to an object or null; it does not contain the object's full contents as a primitive value would.
2.3 Primitive vs reference types
Primitive type	Reference type
One of Java's eight built-in primitive types	Refers to an object or is null
Holds a primitive value	Holds a reference value
Cannot be null	Can be null
Has a corresponding wrapper class	Examples: String, arrays, custom classes


Wrapper classes:
Primitive	Wrapper
byte	Byte
short	Short
int	Integer
long	Long

char	Character

2.4 Variable naming rules
Valid examples:
int age;
int studentMarks;
int _count;
int $price;
Invalid examples:
// int 1number;       // Cannot begin with a digit
// int class;         // Reserved keyword
// int student marks; // Spaces are not allowed
Naming conventions:
- Use meaningful names.
- Use camelCase for variables and methods: studentName, totalMarks.
- Use PascalCase for class names: StudentRecord.
- Use uppercase with underscores for constants: MAX_SIZE.
Example constant:
final double PI = 3.14159;
final prevents reassignment of the variable. For a reference variable, it does not automatically make the referenced object immutable.
2.5 Types of variables by where they are declared
Local variable
Declared inside a method, constructor, or block.
public class Example {
    public static void main(String[] args) {
        int age = 20;
        System.out.println(age);
    }
}
A local variable must be definitely assigned before it is read. It does not receive an automatically usable default value.
Instance variable
A field declared in a class without static. Each object has its own instance field.
class Student {
    String name;
    int age;
}
Static variable
A field declared with static. It belongs to the class and is shared by instances of that class.
class Student {
    static String university = "GLA University";
    String name;
}
2.6 Default values of fields and array elements
Type	Default value
byte, short, int, long	0
float, double	0.0
char	'\u0000'
boolean	false
Reference types	null


These defaults apply to fields and array elements, not to local variables.
2.7 Example program
public class DataTypes {
    public static void main(String[] args) {
        String name = "Mee";
        int age = 20;
        double cpi = 7.86;
        char grade = 'A';
        boolean learningJava = true;

        System.out.println("Name: " + name);
        System.out.println("Age: " + age);
        System.out.println("CPI: " + cpi);
        System.out.println("Grade: " + grade);
        System.out.println("Learning Java: " + learningJava);
    }
}
